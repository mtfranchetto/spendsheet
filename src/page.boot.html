// ------------------------------------------------------------------------- // Loading and drawing // ------------------------------------------------------------------------- /** * Everything the client holds is now a claim about the past. * * Clearing `state.cache` alone was the bug, and it looked like it worked. * That object holds analytics payloads and nothing else, keyed by filter * signature — but `go()` only re-enters a loader when `state.data.analytics` * is null or `state.records.loaded` is false, and neither was touched. An answer fetched this session is the truth and * re-asking for it is a round trip for a value already held. One hydrated out * of storage is last week's answer in this week's shape — drawing it is the * entire point of the cache, and *stopping there* would be a screen that is * never right again. * * So a hydrated slice is drawn and then asked about, once; the answer clears * the mark and it is free for the rest of the session. */ function drawnFromStorage(key) { return !!state.hydrated[key]; } /** * A fresh answer for a slice: store it, and stop calling the old one held. * * `state.cache` is dropped as well as unmarked, because for Records that * entry exists *only* to be hydrated from — nothing reads it once a real * answer is in, and leaving it would keep a 33KB payload alive per set of * filters anyone happened to open.
