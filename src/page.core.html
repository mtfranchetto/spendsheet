There is no round trip left to remove — what is left is to stop *waiting* for them. ## Why storing it here works, which is not obvious The app renders in Apps Script's sandboxed iframe, on a `…-script.googleusercontent.com` origin this project does not own, and the reasonable assumption is that nothing written there survives. Measured on the live platform, in WebKit with an iPhone descriptor and a persistent profile, across three separate browser processes: the origin came back **identical** every time, and a value written by the first process was read back by the second and the third. So it keeps. What that measurement cannot settle is iOS Safari, where this is *third-party storage in a cross-site iframe* and therefore exactly what ITP targets. Which is why every access below is wrapped: a refusal, a quota error, a partitioned bucket and a value someone cleared are all the same answer — **no cache**, and the app behaves as it did before this existed.
