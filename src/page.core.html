The `/exec` document is ~2,400ms of Apps Script container spin-up before a line of page code runs, and every `google.script.run` call adds ~2,700ms of fixed overhead on top of whatever the server actually does. There is no round trip left to remove — what is left is to stop *waiting* for them. ## Why storing it here works, which is not obvious The app renders in Apps Script's sandboxed iframe, on a `…-script.googleusercontent.com` origin this project does not own, and the reasonable assumption is that nothing written there survives. Measured on the live platform, in WebKit with an iPhone descriptor and a persistent profile, across three separate browser processes: the origin came back **identical** every time, and a value written by the first process was read back by the second and the third. So it keeps. What that measurement cannot settle is iOS Safari, where this is *third-party storage in a cross-site iframe* and therefore exactly what ITP targets. Which is why every access below is wrapped: a refusal, a quota error, a partitioned bucket and a value someone cleared are all the same answer — **no cache**, and the app behaves as it did before this existed. There is no failure here worth reporting to anyone, because the fallback is a working app. ## Why the version, and why a mismatch discards A deploy that renames a field in one of these payloads would otherwise hydrate a screen out of a shape the current code cannot read, from a store the person holding the phone has no way to clear. `CACHE_SHAPE` is bumped whenever a cached payload's shape changes, and a mismatch drops the whole thing rather than merging what still fits — a half-recognised payload is the one outcome worse than an empty one. */ var CACHE_KEY = 'spendsheet'; var CACHE_SHAPE = 1; /* How many Charts and Records slices are kept between them. Nothing bounds the number of distinct filter signatures a person can produce — every period against every account against every label — and an unbounded list in a store with no eviction of its own eventually fails a write, which under the wrapping above silently means no cache at all.
